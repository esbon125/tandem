# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Branch structure

This repo uses separate long-lived branches by kind of content — commit accordingly rather than
mixing content types into one branch:

- `docs` — documentation deliverables only (`docs/`: anteproyecto, CIA report, propuesta, bring-up
  logs, reference PDFs). Does not contain `trunk/` at all.
- `hardware_development` — RTL/FPGA work: the `trunk/mpeg2fpga` Verilog port, Libero SoC project
  files, and hardware bring-up (FPGA programming, board-level verification).
- `firmware_development` — software that runs on the PolarFire SoC MSS: bare-metal applications,
  Linux/Yocto bring-up, kernel driver work, and related tooling.

When committing, check which of these a change belongs to and commit on that branch rather than
wherever happens to be checked out; use a separate `git worktree` if the current branch has unrelated
in-progress changes that shouldn't be disturbed.

## Project overview

This is an engineering thesis project ("anteproyecto"/CIA final project) whose goal is to implement,
prototype and optimize an industrial-grade MPEG-2 video decoder (ISO/IEC 13818-2) on FPGA. The core of
the work is porting **mpeg2fpga** — a third-party, Xilinx-oriented open-source Verilog MPEG-2 decoder
(`trunk/mpeg2fpga`, by Koen De Vleeschauwer) — to a **Microchip PolarFire SoC** target (see
`docs/polarfire/`), and eventually running/supporting it from software on that SoC.

Repository layout:

- `trunk/mpeg2fpga/` — the Verilog decoder core and everything needed to simulate it (see below).
- `docs/` — LaTeX sources and PDFs for the academic deliverables (anteproyecto, CIA report, propuesta)
  and PolarFire hardware reference manuals/schematics. These are reference/writeup material, not code.

Because the decoder is licensed third-party MPEG-2 IP (see `trunk/mpeg2fpga/rtl/LICENSE-MPEG2`),
prefer minimal, targeted diffs to `rtl/mpeg2/*.v` over rewrites — most of that tree should stay
close to upstream except where changes are specifically about the PolarFire port.

## Porting work in progress

The current branch (`hardware_development`) is adapting the decoder away from Xilinx-specific
primitives toward vendor-neutral / PolarFire equivalents:

- `rtl/mpeg2/wrappers.v` defines every dual-port RAM and FIFO used in the design (`dpram_sc`,
  `dpram_dc`, `fifo_sc`, `fifo_dc`). Each wraps a `generate if (FIFO_XILINX) ... else ...` choice
  between a vendor "hard" FIFO (`xilinx_fifo_sc.v`/`xilinx_fifo_dc.v`, built from Virtex-5 FIFO18/36
  primitives) and a portable "soft" FIFO implementation (`xfifo_sc.v` / the new `xfifo_dc.v`). When
  porting, set `FIFO_XILINX=0` for the wrapper(s) in question and make sure a working soft-FIFO
  model exists (`xfifo_dc.v` was added for this reason).
- `rtl/mpeg2/mpeg2video.v` top-level module previously took `clk`, `mem_clk`, `dot_clk` as external
  inputs; it now takes a single `ref_clk` and derives the three internal clocks from a `PF_CCC_C0`
  clock-conditioning circuit (PolarFire's Libero-generated PLL/CCC macro). Keep this in mind if
  touching clocking — the three original clock names still exist as internal wires.
- `trunk/mpeg2fpga/mpeg2fpga/` is a Microchip Libero SoC project directory (constraints, synthesis,
  simulation scripts, SmartDesign component defs for `PF_CCC_C0` etc.) generated by the Libero tool —
  treat its contents as tool output/config, not hand-written RTL.
- fifo depth/threshold values live in `rtl/mpeg2/fifo_size.v` and are deadlock-sensitive — see
  `rtl/TODO` and `doc/mpeg2fpga.txt` §2.2.1 before changing them.

## Simulating the decoder (Icarus Verilog)

The only automated test path in this repo is the Icarus Verilog behavioral simulation in
`trunk/mpeg2fpga/bench/iverilog/`.

```sh
# one-time: get a test stream, e.g.
cd trunk/mpeg2fpga/tools/streams
wget ftp://ftp.tek.com/tv/test/streams/Element/MPEG-Video/625/susi_015.m2v
mv susi_015.m2v stream-susi.mpg

# requires Icarus Verilog (apt-get install iverilog)
cd trunk/mpeg2fpga/bench/iverilog
make clean test
```

- `make test` builds `mpeg2` from the file list in the Makefile's `SRCS`/`INCS` vars and runs it;
  the working directory fills with `framestore_*.ppm` / `tv_out_*.ppm` frame dumps to inspect.
- The `STREAM` and `MODELINE` variables at the top of `bench/iverilog/Makefile` select the input
  elementary stream and target video mode (e.g. `MODELINE_SVGA`, `MODELINE_PAL_INTERL`); other test
  streams live under `tools/streams/<vendor>/` (many are MPEG-2 conformance streams).
- When adding a new `.v` file to the decoder core, add it to both `SRCS` (or `INCS` for
  `` `include``-only files) in `bench/iverilog/Makefile` — the simulation won't pick it up otherwise.
- `make cntstmnts` is a rough code-size metric (counts semicolons/lines across the core sources).
- Full-chip conformance test streams and reference outputs are described in
  `trunk/mpeg2fpga/bench/README` and `doc/mpeg2fpga.txt` §2.3.2; `tools/mpeg2dec/` is a reference C
  MPEG-2 decoder useful for comparing decoded output.

There is no synthesis/build step checked into version control for the PolarFire target beyond the
generated Libero project under `trunk/mpeg2fpga/mpeg2fpga/` — synthesis/PnR is expected to be driven
from Libero SoC itself, not from a CLI command in this repo.

## Decoder architecture (rtl/mpeg2)

The core is a fixed-function streaming pipeline, one pixel/word per clock through most stages.
Data flow (see `doc/mpeg2fpga.txt` §2.2.1 and `doc/fifos.ps` for the full diagram):

1. **Stream input → vbuf** (`vbuf.v`): incoming MPEG-2 bytes go through `vbuf_write_fifo` into a
   circular video buffer in external memory, then back out through `vbuf_read_fifo` — this triple
   acts as one big elastic FIFO decoupling input bitrate from decode rate.
2. **Bitstream parsing**: `getbits.v` provides a variable-width sliding window over the stream;
   `vld.v` (variable-length decode, tables in `vlc_tables.v`/`vld_codes.v`) parses headers and
   produces run/length codes and motion vectors.
3. **Reconstruction of prediction error**: `rld.v` (run-length decode) → `iquant.v` (inverse
   quantize, `zigzag_table.v`) → `idct.v` (inverse DCT) produce the decompressed prediction error,
   written to `predict_err_fifo` a row of 8 pixels at a time.
4. **Motion compensation**: `motcomp_addrgen.v` translates motion vectors (via `mem_addr.v`) into
   forward/backward read addresses and a destination write address; `motcomp_picbuf.v`,
   `motcomp_recon.v` etc. fetch reference pixels through the memory subsystem and sum them with the
   prediction error to reconstruct the image, written back to the frame store.
5. **Frame store / memory subsystem**: `framestore.v` + `framestore_request.v` +
   `framestore_response.v` arbitrate all memory reads/writes through a single external-memory port,
   tagging outstanding read requests (`mem_tag_fifo`) so responses can be routed back to the right
   consumer (video buffer, fwd/bwd motion comp, or display resampling). `mem_codes.v` defines the
   memory map (default needs 4 MB RAM/SDTV; `MP_AT_HL` selects a 16 MB HDTV-sized map).
6. **Display path**: `resample_addrgen.v`/`resample_dta.v`/`resample_bilinear.v` do bilinear chroma
   upsampling while scanning the reconstructed image, `yuv2rgb.v` converts color space, `osd.v` overlays
   on-screen display, `pixel_queue.v` crosses from decoder clock to `dot_clk` (video/DVI clock domain),
   and `syncgen.v`/`syncgen_intf.v`/`modeline.v` generate the video timing signals.
7. **Control/misc**: `regfile.v` (register file the driving processor reads/writes), `reset.v`,
   `watchdog.v`, `synchronizer.v` (clock-domain-crossing reset/control signals), `probe.v` (test
   point mux for the logic analyzer, see `tools/logicport/`).

Three independent clock domains run through the design: decode clock (`clk`, multiple of 27 MHz —
MPEG-2 timestamps are 27 MHz-resolution), memory clock (`mem_clk`, ~133–166 MHz), and video/DVI clock
(`dot_clk`, ~25–75 MHz depending on resolution/frame rate). All FIFOs/RAMs crossing these domains go
through the `dpram_dc`/`fifo_dc` wrappers in `wrappers.v` (see Porting work above).

`doc/mpeg2fpga.txt` (plain-text export of `doc/mpeg2fpga.lyx`) is the authoritative user guide for the
decoder — read it before making non-trivial RTL changes, especially the processor interface
(registers, IRQs, watchdog, trick modes) in its Chapter 1.
